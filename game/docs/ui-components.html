사용 규칙
① 새 UI 작업은 반드시 이 페이지의 컴포넌트 목록을 참고한다.
② 목록에 없는 컴포넌트/토큰은 사용 금지. 필요하면 먼저 src/ui/ 와 이 페이지에 추가하라.

④ 새 색/사이즈가 정말 필요하면 ModalPanel.ts 에 토큰을 추가한 뒤 이 페이지의 토큰 섹션도 동기화한다.

Selection State FOUNDATION

SSoT: ROW_SELECTED / SLOT_SELECTED tokens · 모든 리스트·메뉴 컴포넌트가 이 패턴을 따른다

플레이어가 "지금 어디에 커서가 있는가" 를 한 번에 인식하지 못하면 메뉴 UI는 실패한다. Bloodstained: Ritual of the Night 의 메뉴를 기준으로, 선택 상태는 다음 4 레이어를 동시에 적용한다. 어느 한 레이어도 단독으로는 충분하지 않다.

Key Color · Orange (#ffa41b)
청록 액센트는 다크 네이비 모달 패널에서 묻힌다. 선택 상태는 프로젝트의 워밍 톤(주황 단조 팔레트)과 일치하는 오렌지 키컬러로 통일한다. 장착 상태(#ff8c00 bar)와 색상이 겹칠 때는 펄스 + 챠브론 + [E] 배지로 구분한다.

4-Layer Recipe

① Saturated Fill — 비선택과 채도 차이가 충분한 배경 (단색 아님, 좌→우 그라디언트로 깊이 부여)
② Full-Alpha Edge — 2px 액센트 보더, alpha 0.95+ (희미한 outline 금지)
③ Symmetric Chevrons — ▶ (좌) + ◀ (우) 양쪽에 액센트 색상 표시
④ Outer Halo + Pulse — 외부 box-shadow 글로우 + 1.6s 펄스 애니메이션 (정적 UI에서도 살아있는 느낌)

SELECTED — 4-layer 적용
▶ ⚔ Iron Sword ATK 12
▶ ⚔ Steel Blade ATK 28
▶ ⚔ Frost Edge ATK 34

Anti-Pattern (이전 버전, 사용 금지)

다음 예시는 실제 플레이테스트에서 "선택이 명확하지 않다" 피드백을 받은 구버전이다. 단일 outline 35% alpha + ▶ 1개로는 화면 활동량이 많을 때 묻혀버린다.

DEPRECATED — 단일 outline 35% alpha
▶ ⚔ Iron Sword ATK 12
▶ ⚔ Steel Blade ATK 28

Anvil Mode — 배치 이펙트 5단계 (구 §3.8.6, ForgeUI 통합 2026-05-24)

인벤토리에서 아이템 선택 후 [C] 누르면 마름모 anvil 슬롯에 *순차 시각 토큰* 재생. 모든 토큰은 ui_hud_01_atlas.png 의 ui_forge_active slice + GlowFilter 조합.

  1. 비행 (150ms ease-out) — 선택된 그리드 셀 → 마름모 슬롯 중심으로 sprite tween
  2. 착지 스파크 (100ms) — 슬롯 도착 순간 small dust burst (rarity color)
  3. 테두리 플래시 (200ms) — 마름모 outline 이 흰색 → rarity color 페이드
  4. 슬롯 디밍 — 원본 그리드 셀이 alpha 0.4 + "ON ANVIL" 텍스트 오버레이
  5. 맥동 (0.8s loop, alternate) — GlowFilter radius 3~10px 사이 sine 펄스

  • 색 tone 변종:
    • Relic = #FFA41B outer glow + #FFCC66 내측 (ROW_SELECTED_GLOW / ROW_SELECTED_GLOW_INNER 토큰 동일). 능력 = 단조열 오렌지.

    두 변종은 색만 다르고 레이아웃은 동일.
  • Display font: 능력 이름은 Chakra Petch sans-serif (TitleScene 과 동일) + uppercase + letter-spacing 7-8px. PIXEL_FONT 가 아닌 이유 = relic 획득은 의례적 일회성 → 타이틀 톤. 일반 모달 본문(PIXEL_FONT 8/10/12) 과 시각 격차를 분명히.
  • Eyebrow label: "RELIC ACQUIRED" / "HP UPGRADE" 등 카테고리 라벨. PIXEL_FONT 8pt + letter-spacing 4px + 색은 본 glow tint 와 통일. (Max HP 의 lore-flavored 카피 — 예: "PLATE FORGED" — 는 Writer 협의 필요. 현재는 functional copy.)
  • 아이콘 halo: GlowFilter radius 20, intensity 1.0. Anvil halo (radius 14) 보다 강하게 — 픽업 모먼트 강조. 이중 ring (외곽 0.45 alpha + 내측 0.25 alpha) 으로 의례적 디테일.
  • 입력 잠금: LorePopup 패턴 — 모달 떠있는 동안 X/이동/공격 차단. [Z] 또는 [ESC] 로만 닫힘. 모달이 떠있는 동안 RelicAuraBurst column-of-light 가 화면에 잔존하도록 timing 조율.
  • RelicAuraBurst 와 합주: RelicAuraBurst.spawn() 의 column-of-light + ring 이 약 900ms 잔존. 그 위에 본 모달이 200ms 지연 후 fade-in 시작. 단순 픽업 (gold drop, healing) 과 영구 획득 (relic, max HP) 의 시각 격차 확보.
  • 크기/위치: 화면 정중앙. 텍스트 stack 자체는 약 320×260 (아이콘 88 + gap 12 + Chakra Petch 22 + body 11 + hint 8 + 여유). 모바일 / 1920 해상도에서도 비례 유지.

애니메이션 타임라인

  • 0-200ms (entry delay): RelicAuraBurst.spawn() 단독 표시. timeScale 0 으로 게임 정지.
  • 200-600ms (Phase 1): 비넷 alpha 0 → 0.7 fade. 동시에 eyebrow 페이드인 + 아이콘 scale 0 → 1 (ease-out-back, slight overshoot).
  • 600-900ms (Phase 2): 글리프 이름이 y+8 → 0 슬라이드업 + fade-in.
  • 900-1200ms (Phase 3): usage description + continue hint stagger fade-in (간격 100ms).
  • Idle: 아이콘 halo 펄스 1.4Hz (anvil/selection 동일 주기). 글로우 alpha 0.5 → 0.85 sin 변조. 외곽 ring 도 동기.
  • Exit ([Z] / [ESC]): 전체 stack alpha 1 → 0 (220ms ease-out). 비넷 fade-out 동시. timeScale 1.0 복원. 입력 잠금 해제.

WorldPullIn — Center Sink ORGANISM

PixiJS recipe · RenderTexture snapshot + radial sprite displacement · 후보 구현: game/src/effects/WorldPullIn.ts

화면 주변의 월드가 중심 특이점으로 빨려 들어가는 전환 연출. 아이템계 진입, 기억 회수, 붕괴 포털처럼 세계의 좌표계가 접히는 순간에 사용한다. 카메라 자체를 크게 흔드는 대신 월드 snapshot 조각을 중심으로 당겨, UI/HUD는 안정적으로 남기고 배경만 붕괴시킨다.

Preview — 60-slice world collapse

duration=3200ms · center=(camera center) · HUD layer excluded · reduced-motion fallback = static core

PixiJS implementation recipe

Capture: render world/background containers into one RenderTexture. HUD, modal, damage numbers are excluded.
Fragment: create a fixed grid of cropped Texture frames from the snapshot, usually 10×6 or 12×7 at 640×360.
Pull: each sprite stores its original center, vector to sink center, distance, and angle. Over 2.8-3.2s, ease radius toward 0, add small tangential spin, scale down, then fade.
Core: draw a small additive Graphics core plus 5-8 radial streak sprites. This sells suction without warping UI text. 
const rt = RenderTexture.create({ width: viewW, height: viewH });
renderer.render({ container: worldContainer, target: rt });

for (const tile of tiles) {
  const toCenter = {
    x: center.x - tile.home.x,
    y: center.y - tile.home.y,
  };
  tile.sprite.texture = new Texture({ source: rt.source, frame: tile.frame });
  tile.sprite.position.copyFrom(tile.home);
  tile.pull = toCenter;
}

ticker.add(({ deltaMS }) => {
  const t = clamp01((elapsed += deltaMS) / 3000);
  const e = easeInCubic(t);
  for (const tile of tiles) {
    tile.sprite.x = tile.home.x + tile.pull.x * e;
    tile.sprite.y = tile.home.y + tile.pull.y * e;
    tile.sprite.rotation = tile.baseAngle + tile.spin * e;
    tile.sprite.scale.set(1 - 0.92 * e);
    tile.sprite.alpha = 1 - smoothstep(0.72, 1, t);
  }
});

Usage rules

  • Use for: item-world entry, memory recall, world collapse, one-way portal activation.
  • Do not use for: normal hit impact, small pickup, menu open/close. The effect means spatial rupture.
  • Layer rule: apply to world/background/effects layers only. UI and prompt layers stay readable.
  • Performance: cap fragments at 84 sprites. Reuse sprites and RenderTexture; destroy after transition.
  • Accessibility: if reduced motion is enabled, use a 300ms radial vignette + core flash only.

설계 규칙

① 메인은 갭 없음 · 서브만 갭: 메인 슬래시는 중심을 연속으로 관통한다. 서브 교차선만 중심에 갭을 둔다. 결과 — 타격 중심에는 메인만 보이고 베기 방향이 명확해짐
② 메인 1.5× 길이: 서브 교차선 + 갭 구성으로 중심이 시각적으로 비좁아 보일 위험을 메인 길이로 상쇄. 베기 동선이 길게 늘어져 강조됨
③ 서브 갭 크기: Light 18px / Heavy 26px / Crit 34px (서브 길이의 약 25%). 갭이 충분히 커야 중심의 메인이 깨끗하게 분리되어 보이고, 서브 segment 도 끝이 잘려나간 짧은 흔적처럼 읽힌다
④ 서브 Segment 2개로 갭 구성: 각 서브 선은 두 개의 half-segment (forward + backward) 로 그린다. 각 segment 는 갭 가장자리(inner edge)를 anchor 로 잡고 외부로 sweep
⑤ 동적 가중치(Cross Count): segLen = (crossLen/2) - gap 기준으로 cross 수 자동 캡 — 32px↑ 풀 / 22px↑ 3 / 14px↑ 2 / 6px↑ 1 / 6px↓ 0. 갭이 커져도 안 보이는 stub 가 생성되지 않음
⑥ Per-cross 길이 클램프: minCrossLen = (gap + 6) × 2. jitter 가 길이를 더 줄이려 해도 이 값 이상으로 강제. 항상 6px 이상의 visible segment 보장
⑦ 메인 슬래시 각도 = 베기 방향: 한 hit 당 한 각도. 풀: 대각선 내려치기 ( -30°~-15° ), 수평 베기 ( 0°/180° ), 위로 올려치기 ( +15°~+30° ). 정수직 ±90° 회피 (캐릭터 라인 충돌)
⑧ Cross 각도 풀: ±45° / ±60° / ±90° / ±120° / ±135° 중 비복원 추출 + ±10° jitter. 0°/180° (메인과 같은 축) 회피
⑨ 길이 jitter: 메인 ±10% (안정적 형태 유지), 교차선 ±20%. 동일 길이 다발은 인공적, 너무 큰 jitter 는 산만함
⑩ stagger: 메인 0ms 즉시 발사 (베기 신호). 교차선 8~50ms 순차 발사. 메인 → 교차 → 파편 의 시간 차가 임팩트 깊이를 만든다
⑪ 그라디언트 fade: 메인은 양 끝 모두 transparent → 중심 풀 흰색. 서브 segment 는 inner edge (갭 쪽) transparent → outer 50% 풀 흰색 → outer edge fade
⑫ 버스트 색 = 단조열: #ff8833 (DEC-035 키컬러 정합). 적 종류별 변동 금지 — 임팩트는 무기 발사 신호이지 적 신호가 아님
⑬ Hit Stop: Heavy 이상에서만. Light 약공격은 0 (콤보 흐름 보호). Sekiro/HK 모두 동일
⑭ Shake 축 = 메인 방향: 베기 방향에 평행한 흔들림. 무지향 random shake 보다 타격 방향감 강화
⑮ 예산: 메인 1 + 서브 segment 최대 8 / 파편 80 / 버스트 4 (씬당). DOM 노드는 setTimeout 으로 정리
⑯ reduce-motion: segment·파편 0.6× 길이 + 즉시 페이드, shake/burst 비활성. 가독성은 유지

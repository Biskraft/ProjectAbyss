> **문서 ID:** TOOL-SPECCANVAS

> **최근 업데이트:** 2026-06-05

## 0. 목적

전체 스펙 자산(`Documents/**/*.md` + `Sheets/*.csv`)을 **편집 가능한 도형 노드**로 시각화하고, 도형 간 **연결선**으로 관계를 표현하는 자유 배치 캔버스. 카드(도형)의 존재·정체·메타데이터는 **실제 파일(SSoT)에서만** 파생되며, 보드는 그 위의 뷰일 뿐이다.

## 1. 라이브러리 결정 — JointJS (오픈소스 코어)

누적 요구 전체에 대한 평가:

| 요구 | Fabric.js | Konva.js | jsPlumb(Community) | **JointJS** |
| :--- | :---: | :---: | :---: | :---: |
| 자유 배치(스냅 불필요) | ✓ | ✓ | ✓ | ✓ |
| 도형 리사이즈/형태 변경 | ✓ | ✓(Transformer) | ✓(CSS) | ✓ |
| 이미지 채움 + 자동 맞춤 | ✓(clipPath) | ✓(clip) | ✓(object-fit) | ✓ |
| **도형 간 연결선(앵커·이동 추종)** | ✗ 수동 | △ 수동 | ✓✓ 특화 | ✓✓ 1급 |
| 직렬화(자동 저장 라운드트립) | ✓✓ | ✓ | ✓ | ✓✓(`graph.toJSON`) |
| 168+ 노드 규모 성능 | △ | ✓✓ | ✗ 가상화 없음 | ✓✓ 가상 렌더 |
| 바닐라(단일 HTML+CDN) | ✓ | ✓ | ✓ | △ 의존성 3 |

→ **JointJS** = 연결선 1급 + 대규모 성능 + 그래프 직렬화를 동시에 만족. **Konva**는 의존성을 더 줄이고 싶을 때의 대안(연결선 수동). Fabric/jsPlumb는 각각 연결선 약점/규모 성능 약점으로 제외.

## 2. 요구사항 매핑

| 요구 | 구현 |
| :--- | :--- |
| 스냅 불필요 | 자유 변형, 스냅 미적용 |
| 도형 형태 조정 | 리사이즈 핸들 + 도형 타입(사각/둥근사각/타원/다각형) |
| 도형에 이미지 + 자동 축소 | JointJS 이미지 엘리먼트, `xlink:href` + `preserveAspectRatio`(contain) → 도형보다 크면 축소, 리사이즈 시 재맞춤 |
| 도형 간 연결선 | JointJS Link(앵커/라우터). 노드 이동 시 자동 추종, 화살표/꼭짓점/삭제 도구 |
| 최상위 문서가 모든 문서 흡수 | 서버가 SSoT 스캔 → 노드 주입 |
| 툴 수정 시 자동 저장 | 그래프 변경 이벤트 → 디바운스 PATCH(저장 버튼 없음) |
| 문서 업데이트 시 갱신 | `fs.watch` + SSE → 재조정 |
| 문서는 비시각적 | 백킹은 순수 JSON |

## 3. 아키텍처

```
game/tools/spec-canvas/
├─ SPEC.md            # 이 문서 (도구 SSoT, Documents 흡수 대상 아님)
├─ spec-canvas.html   # JointJS(CDN). 캔버스 + 도형/이미지/연결 패널
└─ server.mjs         # node http :4331
      ├─ GET  /board        → 재조정된 노드/엣지 + 뷰상태
      ├─ POST /patch        → 뷰상태 변경 즉시 기록(디바운스)
      ├─ GET  /assets       → game/public/assets 이미지 목록
      └─ GET  /events (SSE) → 파일 변경 실시간 푸시
npm script: "spec-canvas": "node tools/spec-canvas/server.mjs"
```

## 4. 데이터 모델 — SSoT vs 뷰상태 (엄격 분리)

- **SSoT(진실):** 실제 파일 `Documents/**/*.md`, `Sheets/*.csv`. "어떤 스펙이 존재하는가 / 정체 / 메타"의 유일한 출처.
- **노드 정체 키:** 문서 헤더의 `> **문서 ID:**`(있으면). 없으면 정규화된 파일 경로.
- **뷰상태(`Documents/Plan/Spec_Board.json`):** 도형 타입·좌표·크기·이미지·스타일 + 엣지 `[{from, to}]`. **키는 스펙 정체.** 스펙 존재 여부의 출처가 아님(뷰 전용).

## 5. SSoT 무결성 — 재조정(Reconcile)

로드 시 + 모든 `fs.watch` 변경 시 서버가 수행. "없는 스펙·제거한 스펙" 발생을 **구조적으로 불가능**하게 만든다.

1. SSoT 스캔 → 존재 스펙 집합 `S`.
2. 뷰상태 카드 집합 `B`.
3. **신규(`S − B`):** 기본 도형 노드 자동 생성(미배치 존).
4. **고아(`B − S`):** 노드 + 뷰상태 + 연결된 엣지까지 **삭제(GC)**. 유령 카드 0.
5. **공통(`S ∩ B`):** 바인딩 메타(제목/상태/수정일) 파일에서 갱신. 사용자 배치·도형·이미지는 보존.
6. **이름변경/이동:** 안정 ID(문서 ID)로 추적 → 경로만 갱신. ID 없는 문서는 remove+add로 처리(한계 — ID 부여 권장).
7. **엣지 무결성:** 양 끝 중 하나라도 사라진 엣지는 제거.
8. **중복 ID 검출:** 동일 문서 ID 2건 이상 시 경고.

결과: 보드 노드 집합 ≡ SSoT 스펙 집합 (항상). 도구에서 카드를 "삭제"해도 파일이 남아 있으면 다음 재조정에서 복원 → **도구로 스펙을 지울 수 없다(SSoT 우위 강제).** 도구는 스펙 파일을 생성/삭제하지 않는다(읽기 전용).

### 노드 종류 분리

- `spec` 노드: SSoT 바인딩, 재조정 대상. 자유로 생성/삭제 불가.
- `annotation` 노드(선택): 라벨·그룹 박스 등 스펙과 무관한 자유 도형. 뷰상태에만 존재, 재조정 제외. "스펙으로 위장한 유령" 방지를 위해 시각적으로 명확히 구분.

## 6. 도구 자체의 프로젝트 SSoT 준수

- **로컬라이제이션:** 본 도구는 게임 빌드 비포함 내부 도구이므로 `Content_Localization.csv` 등록 대상 아님(게임 내 문자열 한정 P0, `hud-tool` 선례, 디버그 예외와 동급).
- **UI 컴포넌트 가이드:** 게임 내 PixiJS UI 한정 규칙 — 독립 HTML 도구는 비대상(`hud-tool.html` 선례).
- **데이터 SSoT:** 도구는 CSV/문서를 **읽기만** 한다. 경쟁 진실 출처가 되지 않는다. 뷰상태(`Spec_Board.json`)는 좌표/도형/이미지/엣지만 보유.
- **마크다운 링크 규약:** 본 문서 내 링크/경로 뒤 공백 유지.

## 7. 단계별 계획

1. **v1:** JointJS 캔버스 + 도형 3종 자유배치·리사이즈 + 이미지 드롭 자동맞춤 + 연결선 + 그래프 자동저장.
2. **v2:** 서버 SSoT 스캔·재조정 + `fs.watch`/SSE 라이브 + 에셋 피커 + 상태/태그 색.
3. **v3:** 다각형/자유 패스, 이미지 cover/contain 토글, 그룹·창발 군집(헐) 시각화, annotation 노드.
4. **(선택):** 엣지 의미 타입(의존/참조/상충) + 이를 GDD 교차참조 검증과 연계.

## 8. 확정 필요한 결정

- **라이브러리:** JointJS(권장) vs Konva(의존성 최소·연결선 수동).
- **뷰상태 git 추적:** `Spec_Board.json`을 추적(배열 버전관리) vs 좌표 로컬 전용.
- **이미지 맞춤 기본값:** contain(전체 축소) vs cover(채움 크롭).
- **annotation 노드:** 자유 비스펙 도형 허용 여부.

## 1. 문제

현 `Player.stateAttack`(≈1568)은 **지상 콤보 중 감속 자유이동(슬라이드)** 을 허용한다:
```
지상: applyHorizontalInput(ATTACK_MOVE_MULT)   // 슬라이드
공중: AERIAL_ATTACK_MOVE_MULT = 0.05            // 거의 정지(앵커)
```
- 스윙 애니는 발이 박혀 있는데 캐릭터는 미끄러짐 → **시각 정합성 desync**.
- 콤보 중심 액션게임은 대부분 "스윙 중 자유이동"을 주지 않는다(조사: Souls·DMC·Hades·God of War·Monster Hunter). 기동성은 **스윙당 전진 런지 + 스윙 사이 캔슬**로 만든다.
- 공중은 이미 앵커(0.05)인데 지상만 어긋나 있다 — 결을 통일해야 한다.

---

## 2. 설계 방향 — "스윙당 루트 + 런지 + 캔슬"

DMC/Hades 중간형. 핵앤슬래시(아이템계 다수 몹)라 Souls식 완전 끈적임은 배제, **커밋 후 재배치 리듬**(리듬>그라인드).

| 레버 | 변경 | 효과 |
|:--|:--|:--|
| **루트(active)** | 스윙 active 프레임 = 수평 이동 0(또는 0.05, 공중과 통일) | 발-위치 정합 |
| **런지(lunge)** | 스윙 시작 시 스크립트 전진 스텝(root motion) | 슬라이드 대신 "내딛는" 무게감 + 갭 클로징 |
| **캔슬 윈도** | 회복/`comboWindowTimer` 구간 대시·점프 캔슬 허용 | 스윙 *사이* 재배치(유려함) |
| **커밋 점증** | 1타<2타<3타 루트·런지·회복 증가 | 마무리 무게 + 리스크 |

> 슬라이드(스윙 중 자유이동)는 **폐기**. 이동 입력은 스윙 active 동안 위치를 바꾸지 않고, 회복/콤보윈도에서만 런지·캔슬·다음 입력으로 반영.

---

## 3. 구체 변경 (코드 타깃)

1. **`stateAttack` 수평 입력** — active 프레임 동안 `moveMul=0`(지상도). pre-active/recovery 구간은 캔슬 입력만 허용.
2. **런지** — `startAttack`에 per-step 전진 임펄스 추가(`COMBO_STEP_LUNGE[comboIndex]`). 기존 `HitManager.startHitAdvance`(hit 시 micro-advance)와 분리: 런지=스윙 시작 시 항상(miss 무관), hit-advance=명중 시 추가.
3. **캔슬** — 회복 구간에서 대시(`startDash`)·점프 입력 시 attack state 조기 종료. `comboWindowTimer`로 다음 타 버퍼 유지.
4. **공중 통일** — `AERIAL_ATTACK_MOVE_MULT`(0.05)과 지상 active 루트를 동일 철학으로(미세 이동 여부는 §6 튜닝).

---

## 4. 커밋 점증 파라미터 (시작값, 튜닝 대상)

| 타 | 루트(active 이동) | 런지(전진 px) | 회복 | 캔슬 가능 |
|:--|:--|:--|:--|:--|
| 1타 | 0 | 소(6~8) | 짧음 | 회복부터 |
| 2타 | 0 | 중(8~12) | 중 | 회복부터 |
| 3타(마무리) | 0 | 대(14~20) | 긺 | 회복 후반만(커밋↑) |

> ECHORIS는 이미 `COMBO_STEP_TIME_MUL`로 3타를 늘리고 공중 3타를 앵커한다 — 이 결을 지상 런지·캔슬로 확장.

---

## 5. 핵심 난제 · 공정성

- **런지 ≠ 슬라이드:** 런지는 스윙 시작 시 *짧은 임펄스*(고정 거리)여야 한다. 입력 비례 이동은 금지(그게 슬라이드).
- **벽/적 충돌:** 런지 중 벽·적 충돌 시 전진 정지(기존 `rx.collided → vx=0` 재사용). 적 관통 금지.
- **반응성 보존:** active 루트가 "끈적임"으로 느껴지지 않도록 — 회복을 짧게, 캔슬을 관대하게. 핵앤슬래시 템포 유지.
- **공중 정합:** 공중 런지는 약하게(공중 앵커 0.05 유지). 공중 3타 near-halt 보존.
- **다수 몹 대응:** 런지가 갭 클로징을 겸하므로, 슬라이드 제거로 인한 기동성 손실을 런지+대시캔슬이 보상하는지 체감 검증.

---

## 6. 구현 체크리스트

- [ ] `stateAttack` — active 프레임 수평 이동 0(지상). pre/recovery 캔슬 입력만.
- [ ] `COMBO_STEP_LUNGE[]` 상수 + `startAttack` 런지 임펄스.
- [ ] 런지 충돌 정지(벽/적), 관통 금지.
- [ ] 회복 구간 대시·점프 캔슬 + `comboWindowTimer` 버퍼.
- [ ] 커밋 점증(1/2/3타 런지·회복 차등).
- [ ] 공중 결 통일(앵커 보존).
- [ ] 상수 토큰화(`PlayerConst` / CSV) — 매직넘버 금지.

---

## 7. 인수 기준

1. **시각 정합:** 스윙 active 동안 캐릭터 위치가 입력으로 미끄러지지 않는다(발-위치 일치).
2. **런지:** 각 타가 시작 시 고정 거리 전진하며, 입력 크기와 무관하다(슬라이드 아님).
3. **벽/적:** 런지 중 벽·적 충돌 시 전진이 멈추고 관통하지 않는다.
4. **캔슬 기동:** 회복/콤보윈도 구간에서 대시·점프로 스윙을 끊고 재배치할 수 있다.
5. **커밋 점증:** 3타 마무리가 1타보다 명백히 큰 런지·긴 회복·강한 커밋으로 읽힌다.
6. **템포:** 다수 몹 상대에서 슬라이드 제거 후에도 핵앤슬래시 반응성이 유지된다(런지+대시캔슬 보상).
7. **공중 보존:** 공중 콤보 앵커(특히 3타 near-halt)가 회귀 없이 유지된다.

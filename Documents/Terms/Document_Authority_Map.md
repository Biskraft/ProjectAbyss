# 문서 권위 계층 지도 (Document Authority Map)

> **문서 ID:** T-07
> **최근 업데이트:** 2026-06-01
> **위상:** 계층 정합성 시스템의 backbone. 상위 문서가 하위 문서의 권위 기준이며, 하위는 상위를 위배할 수 없다. 상위 갱신 시 재검증 대상 하위를 식별한다.

## 0. 목적

단일 문서가 아니라 문서 계층 전체의 정합성을 검증하는 시스템을 정의한다. Design·Terms 등 상위 문서를 권위로 삼아 System·Content 등 하위 문서가 그에 부합하는지 검증한다. 상위를 갱신하면 그에 의존하는 하위만 재검증되는 전파 구조를 갖춘다.

## 1. 두 권위 축 (직교)

| 축 | 권위 방향 | 담당 | 예 |
| :--- | :--- | :--- | :--- |
| 규칙/원칙 축 | 상위 → 하위 (top-down) | 본 시스템 (Layer 6) | D-01 2-Space 원칙을 SYS-WLD가 위배하면 안 됨 |
| 수치 축 | CSV → 문서 (SSoT) | gdd-integrity-checker Layer 1 | 무기 BaseATK는 CSV가 권위, 문서는 맞춤 |

두 축은 직교한다. 본 시스템은 규칙 축(의미 정합)을 담당하고, 기존 Layer 1이 수치 축을 담당한다. 따라서 본 시스템은 평면 checker(Layer 1-5)에 더하는 Layer 6(계층 정합)이다.

## 2. 계층 (Tier)

| Tier | 문서군 | 권위 범위 |
| :--- | :--- | :--- |
| 0 — Constitution | CLAUDE.md, Glossary(T-03), GDD Writing Rules(T-02) | 전역. 모든 문서가 준수 |
| 1 — Design/철학 | D-01~D-20 | 도메인 원칙. 해당 System 권위 |
| 2 — System | SYS-* | 메커닉 구현 규칙. 해당 Content/CSV 권위 |
| 3 — Content/UI/Spec | CNT-*, UI-*, PLN-Spec | 인스턴스화. 상위 규칙 준수 |
| 4 — Data | Sheets/*.csv | 수치 축 권위(별도) |

상위일수록 추상·불변, 하위일수록 구체·파생. 하위는 모든 조상 문서를 위배할 수 없다.

## 3. 도메인 SSoT (중간 권위 노드)

특정 영역을 통합 권위로 갖는 문서. 해당 영역 하위는 이 노드를 최우선 준거로 삼는다.

| SSoT | 권위 영역 | 종속 하위 |
| :--- | :--- | :--- |
| Glossary (T-03) | 모든 용어·폐기어 | 전 문서 |
| D-20 World Master | 월드 구조·구역·게이트·거점 | SYS-WLD-*, 월드 Content |
| D-07 Economy | 경제·골드 sink·상점 철학 | PLN-SHOP, SYS-ECO-* |
| PLN-RELIC | 렐릭 11종 정의 | 렐릭 언급 전 문서 |
| D-01 2-Space | 월드/아이템계 분리 | 전 시스템 |

도메인 SSoT가 상위 Design 원칙과 충돌하면 상위 Design이 우선(Tier 순).

## 4. 의존 선언 규약 (machine-parseable)

각 문서 헤더에 한 줄을 둔다. 파서가 이 줄을 읽어 부모→자식 역인덱스를 만든다.

```
> **준거 상위 (Authority):** T-03, D-01, D-04, D-20
```

- ID는 Document_Index 등록 ID(T-/D-/SYS-/CNT-/UI-/PLN-).
- 여러 상위는 쉼표 구분.
- 선언 누락 = 계층 미연결 → 시스템 자체 경고(검증 사각 방지).
- 기존의 자유형 "정합:" / "근거 문서:" 라인은 본 규약으로 점진 이관.

## 5. 위배 정의 (Layer 6 검출 대상)

하위 문서가 다음에 해당하면 위배:

1. 상위가 폐기한 용어·개념을 사용 (Glossary 폐기어, deprecated_terms).
2. 상위 결정(DEC, 확정값, 규칙)과 다른 값·규칙을 기술.
3. 상위 정의와 모순되는 정의를 둠.
4. 상위가 SSoT라 선언한 영역을 독자 재정의.
5. 상위가 변경됐는데 하위가 옛 기준을 잔존(stale).

> 예: D-20이 "수직 하강 → 상승 주축"으로 갱신됐는데 SYS-WLD-01이 여전히 "하강"이면 §5-2/5 위배. (실제 발생 사례)

## 6. 검증 프로세스 (Layer 6 — Hierarchy Consistency)

1. 변경 감지: git diff로 변경된 상위 문서 식별.
2. 영향 식별: 역인덱스로 해당 상위를 준거로 선언한 하위 목록 추출.
3. 의미 검증: 각 하위를 상위의 캐논 주장(결정·정의·제약)과 대조(의미 비교 — 정규식 아님). 모순 플래그.
4. 보고: 하위 문서:라인, 위배 진술, 위배된 상위 주장, 권고(하위 수정 또는 상위 재확인).

검증은 의미 비교이므로 LLM 에이전트 기반(정규식 불가). 평면 Layer 1-5와 달리 Layer 6은 semantic.

## 7. 전파 / staleness

- 상위 갱신 → 그를 준거로 선언한 하위만 "재검증 필요" 마킹(전체 재검증 회피).
- 역인덱스 스크립트: 전 문서의 준거 선언 파싱 → 부모→자식 맵 → 변경 상위 입력 → 재검증 큐 출력.
- 큐를 Layer 6 검증에 투입.

## 8. 기존 시스템 통합

- gdd-integrity-checker: Layer 1-5(평면) + 신규 Layer 6(계층) = 6레이어.
- 일일 원격 루틴(trig_01GTCuewtMDdKcmKbSJeqek4)에 Layer 6 추가 → 매일 계층 드리프트 탐지.
- 본 지도(T-07)가 Layer 6의 규칙 SSoT.

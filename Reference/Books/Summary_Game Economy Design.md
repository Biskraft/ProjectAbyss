## 장별 요약

### Chapter 1: Outlining Game Economy Design

#### 게임 경제란 무엇인가
- 실세계 경제의 단순화된 통제 버전으로, 게임 내 자원, 화폐, 가상 재화를 중심으로 작동
- 게임 경제 디자이너는 플레이어의 장기 참여를 설계하는 게임 디자인의 하위 전문 분야

#### 게임 경제의 목표 (6가지)
1. **직접적 플레이어 참여 촉진:** 액션 페이즈에 가치와 맥락 부여
2. **장기 플레이어 경험 제공:** 통제된 자원 분배로 정기적 복귀 유도
3. **콘텐츠 배포 접근/통제:** 진행 시스템이 콘텐츠 소진을 방지하는 브레이크 역할
4. **참여와 재미 생성:** 스프레드시트로 측정 불가한 "재미" 요소의 중요성
5. **적응성과 성장:** 출시 후 확장 가능한 구조
6. **수익화 접근:** 인앱 결제와 일반 경제의 시너지

#### 핵심 구성요소
- **화폐(Currencies):**
  - 소프트 커런시: 게임플레이로 획득, 업그레이드/구매에 사용
  - 하드 커런시: 실제 금전 구매, 화장품/프리미엄 콘텐츠에 사용
- **재화(Goods):** 무기, 방어구, 화장품 등 플레이어가 소유하는 주요 아이템
- **자원(Resources):** 특정 목적을 위해 수집되는 전구체 아이템 (예: 금속 조각 -> 검 제작)
- **소스(Sources/Faucets):** 화폐/자원을 경제에 주입 (예: 레벨 완료 보상)
- **싱크(Sinks/Drains):** 화폐/자원을 영구 제거 (인플레이션 방지)
- **컨버터(Converters):** 한 종류를 다른 종류로 변환 (크래프팅 시스템의 핵심)
- **트레이더(Traders):** 엔티티 간 교환 (생성/파괴 없이 이전만 수행)

#### 장르와 비즈니스 모델
- **Free-to-Play:** 무료 진입, 비강제적 마이크로트랜잭션. 단일 코어 메서드 + 측정 가능한 세션
- **프리미엄:** 선불 구매, 자기 완결적 여정 허용. 다양한 도전과 경험의 혼합
- **Paymium:** 프리미엄 게임 + 인게임 마이크로트랜잭션

#### 플레이어 동기 부여의 3대 질문
1. 타겟 오디언스는 누구인가?
2. 어떤 감정을 유발하고자 하는가?
3. 플레이어가 게임 내에서 무엇을 하는가?

#### 경제 개발의 이론적 구성요소
- **활동(Activities):** 플레이어가 하는 핵심 행동 (전투, 일일 챌린지, 보스 레이드)
- **강도(Intensity):** 활동의 시간/노력 요구 수준 -> 보상 수준 결정
- **보상(Rewards):** 화폐, 자원, 재화의 정의와 연결
- **사용자 여정(User Journey):** 초기 온보딩 -> 중반 -> 엔드게임의 단계별 설계

### Chapter 2: Game Economy and the Metagame

#### 코어 루프 (Core Loop)
- 모든 게임은 액션(강한 참여) <-> 휴식(메뉴, 정보 확인)의 반복 순환
- 코어 루프 시각화: 자원 흐름, 싱크/소스, 수익화 요소를 하나의 다이어그램에 매핑
- **예시(Project X):** 모바일 F2P FPS
  - 소프트 커런시(Cash) + 하드 커런시(Gold)
  - 경험치 -> 계정 레벨업 -> 무기 해금
  - 무기 연구 토큰 -> 무기 업그레이드
  - 배틀패스 경험치 -> 코스메틱 보상

#### 메타게임 구성요소
- 메타게임 = 코어 게임플레이를 둘러싼 시스템과 메커닉의 집합
- 게임 경제는 메타게임에서 태어나며, 플레이어가 여러 곳에서 "느끼는" 이론적 개념

#### 진행 시스템 설계
- 테니스 초보자의 학습 여정 비유: 후크 -> 기본기 -> 중급 -> 고급 -> 엘리트
- **사용자 여정의 단계:**
  - **온보딩/초기:** 빠른 진행, 최소 노력으로 성취감, 사전 정의된 선형 경험
  - **중반:** 습관 강화, 시스템 이해 심화, 개인 전략 개발, 사회적 기능 활용
  - **엔드게임:** 새로운 경험(PvP, 던전 레이드), 시즌 리셋, 고유 보상
- **진행 곡선:** 초기에 급속 성장 -> 시간이 지남에 따라 완만해짐 -> 엔드게임에서 평탄화

#### 수직/수평 진행
- **수직 진행(Vertical):** 장비 파워의 직접적 증가 (무기 업그레이드 = 더 강한 데미지)
- **수평 진행(Horizontal):** 다양성 확대, 파워 차이 없음 (Call of Duty: MW의 무기 모디피케이션)

#### 희귀도 시스템 (Rarity Systems)
- Common, Uncommon, Rare, Epic, Legendary의 5단계
- 용도: 품질 즉시 인식, 희소성 감정, 콘텐츠 카탈로그 확장, 프리미엄 코스메틱 차등화
- 진행 시스템과 연동하여 아이템의 계획적 구식화(obsolescence) 유도

#### 스킬 트리와 퍼크
- 스킬 트리: 능력의 순차적 해금, 제한된 장착으로 전략적 깊이
- 퍼크: 보너스/파워업, 무기/장비에 슬롯으로 장착

#### 설계 과제와 이론적 고려사항
- **콘텐츠 페이싱:** 너무 빠른 소진(burn) vs. 너무 느린 배포의 균형
- **대체 가능성(Fungibility):** 화폐(대체 가능) vs. 부스터(대체 불가능)의 구분이 시스템의 핵심
- **분할 가능성(Divisibility):** 소프트 커런시 기본값은 큰 수(1000 기반)로 설정하여 유연성 확보
- **플레이어 계획과 깊이:** 결정론적 보상(예측 가능) + 비결정론적 보상(랜덤, 희귀)의 시너지
- **플레이어 좌절과 실패 가능성:** 실패의 가능성이 있어야 참여가 유지됨
- **복잡성과 혼란:** "Keep it simple, stupid" 원칙. 스프레드시트는 재미를 측정하지 못함
- **소유 효과(Endowment Effect):** 소유한 것의 가치를 과대평가하는 심리 -> 랜덤 드롭의 희귀 아이템으로 활용
- **피크-엔드 규칙(Peak-End Rule):** 경험의 가장 강렬한 순간과 마지막 순간이 기억을 지배
- **스토리텔링과 내러티브:** 메타게임 기능을 세계관에 연결하는 것의 중요성

### Chapter 3: Processes, Design Skills and Development Strategies

#### 게임 디자인 문서 (GDD)
- 단일 표준 형식은 없음 -- 장르, 규모, 스튜디오에 따라 다름
- **문서 헤더:** 문서명, 버전, 소유자, 관련자, 날짜, 상태, 이전 버전 링크
- **본문 구성:** 개요, 설계 의도, 기능 세부사항, 목업/다이어그램, 제약사항, 종속성
- **기능 설계 문서 예시:** 일일/주간 미션 시스템의 설계

#### 스프레드시트
- 게임 경제 디자이너의 핵심 도구
- 주요 함수: SUM, RAND, RANDBETWEEN, VLOOKUP
- **시뮬레이션 구축:**
  - 계정 레벨 진행: 삼각수(Triangular Numbers) 기반 경험치 요구량
  - 랜덤 보상 드롭: 확률 기반 아이템 분배 시뮬레이션

#### 파이프라인과 구현
- 설계 -> 프로그래머 협업 -> 게임 내 구현 -> 테스트의 흐름

#### 수학 기초
- 대수적 조작(변수 치환, 괄호 전개)
- 이차방정식의 실용적 예시
- **쿠폰 수집가 문제(Coupon Collector Problem):** N개의 고유 아이템을 모두 수집하는 데 필요한 평균 시도 횟수 계산

### Chapter 4: Monetization

#### 수익화 전략 3가지
1. **성과(Performance):** 게임플레이 성능을 향상시키는 아이템 판매
2. **선호(Preference):** 플레이어 선호에 맞춘 콘텐츠 판매
3. **개인화(Personalization):** 순수 코스메틱 아이템 판매 (가장 건전한 모델)

#### 수익화 구성요소
- **마이크로트랜잭션(하드 커런시):** 실제 금전으로 프리미엄 화폐 구매
- **소모품(Consumable) vs. 내구품(Durable)**
- **광고:** 배너, 삽입 광고, 보상형 동영상 광고
- **배틀패스:** 장기 참여 + 수익화 동시 달성. 업계 표준 $10
- **다운로드 콘텐츠(DLC):** 확장팩, 시즌패스
- **구독:** 월간 프리미엄 서비스
- **루트박스:** 확률형 아이템 (규제 이슈 주의)

#### F2P 수익화 기법
- **핀치 포인트(Pinch Points):** 의도적 자원 병목으로 결제 유도
- **에너지 시스템:** 플레이 세션 제한, 대기 시간의 수익화
- **손실 회피(Loss Aversion):** 보상 제거 위협으로 참여 유지

#### 화장품 아이템 유형
- 캐릭터 스킨, 무기 스킨, 차량 스킨, 이모트/애니메이션, 로딩 스크린, 엠블럼/배너, 펫/동반자, 패턴/스티커/데칼, 색상

#### 프리미엄 인게임 상점
- **번들:** 테마별 묶음 판매, 개별 판매와의 카니발라이제이션 주의
- **할인:** 전략적 할인, 긴급성 유발
- **추천 페이지:** 콘텐츠 프로모션의 핵심
- **가격 앵커링(Price Anchoring):** 비싼 상품을 먼저 보여줘 다른 상품이 저렴하게 느껴지게
- **미끼 효과(Decoy Effect)와 타협 효과(Compromise Effect)**
- **베버의 법칙(Weber's Law):** 차이를 인식하는 최소 변화량 (JND)
- **SKU 모델:** 5단계 가격 체계 (저가~고가, 보너스 증가)

### Chapter 5: Maintaining the Systems

#### Games as a Service (GaaS)
- 출시 후 지속적 업데이트, 수정, 콘텐츠 추가가 핵심

#### 라이브 운영
- **콘텐츠 순환(Cycling):** 시즌별 콘텐츠 회전, 초기 프리미엄 -> 시간 경과 후 일반화
- **콘텐츠 트레드밀:** 장기 업그레이드 시스템, 에너지 시스템, 소프트 커런시 인플레이션 관리
  - C-Stacks: 소프트 커런시의 계층적 활용으로 인플레이션 통제
  - 퓨전 시스템: 아이템 합성을 통한 싱크 역할
- **콘텐츠 계획:** 시즌별 배포 계획, 진행 시뮬레이션

#### 분석과 메트릭스
- **핵심 KPI:**
  - DAU/MAU (일간/월간 활성 사용자)
  - 세션 수/길이
  - 리텐션 (1일, 7일, 30일)
  - 전환율 (무료 -> 유료)
  - ARPDAU / ARPPU (사용자/결제자당 평균 매출)
  - LTV (생애 가치)
  - 이탈률(Churn Rate)
- **Stickiness:** DAU/MAU 비율로 측정하는 사용자 습관 형성도
- **Bartle Taxonomy:** Achievers, Explorers, Socializers, Killers의 4유형

### Chapter 6: Getting into the Business

#### 게임 산업의 직군
- **게임 디자인:** 시스템/콘텐츠/내러티브/UI/기술 디자이너
- **프로그래밍:** 게임플레이/엔진/UI/네트워크 프로그래머
- **아트:** 컨셉/3D/애니메이션/이펙트 아티스트
- **프로덕션:** PM, 프로듀서

#### 진입 팁
- 인턴십, QA(게임 테스팅)로 시작
- 책/기사 읽기, 네트워킹, 자기 PR

#### 경제 디자이너로 일하기
- 문제 해결 능력이 핵심
- 스프레드시트와 수학에 익숙해야 함
- 다른 디자이너 및 프로그래머와의 협업 필수

### Chapter 7: Case Studies

#### Marvel Snap
- **코어 루프:** 카드 대전 -> 부스터/크레딧 획득 -> 카드 업그레이드 -> 컬렉션 레벨 상승
- **진행 시스템:** 컬렉션 레벨이 새 카드 해금, 부스터(비대체)와 크레딧(대체)의 이원 시스템
- **핀치 포인트:** 부스터는 풍부하지만 크레딧은 부족 -> 결제 유인
- **수익화:** Gold로 변형 카드 구매, 일일 미션 리필, 크레딧 직구매, 시즌패스
- **시즌패스:** 실제 화폐로 직접 구매 (Gold가 아닌), 신규 카드 + 변형 + 다양한 보상

#### The Finals
- **장르:** F2P FPS, 환경 파괴 강조
- **진행:** VRs(소프트 커런시)로 무기/장비 해금, VRs 보유 상한 존재
- **수익화:** 개인화(Personalization) 전략 전면 채택 -- 코스메틱만 판매

## 핵심 인용/개념

- **"Game economy design is a problem-solving role."** - 게임 경제 설계는 문제 해결 역할
- **소스-싱크 균형:** 경제의 안정성은 생성(소스)과 제거(싱크)의 균형에 달려 있음
- **핀치 포인트(Pinch Point):** 의도적으로 설계된 자원 병목 -> 유료 결제 또는 추가 참여 유도
- **결정론적 + 비결정론적 보상:** 예측 가능한 보상으로 습관 형성 + 랜덤 보상으로 흥미 유지
- **콘텐츠 페이싱:** 너무 빠르지도(burn), 너무 느리지도(block) 않은 적정 속도
- **피크-엔드 규칙:** 게임 세션의 마지막 보상이 전체 경험에 대한 인상을 결정
- **소유 효과:** 플레이어가 아이템을 소유하면 실제 가치 이상으로 소중히 여김
- **대체 가능성:** 화폐(대체 가능)와 특수 자원(대체 불가능)의 구분이 경제 설계의 핵심 축
- **"Keep it simple, stupid":** 복잡성은 자연스럽게 발생하므로, 시작은 단순하게

## ProjectZ 시사점

### 1. 코어 루프와 자원 흐름 매핑
- ProjectZ의 코어 루프를 Project X 예시처럼 시각화:
  - **액션 페이즈:** 좀비와 전투, 건물 건설/방어, 타 팀과 교전
  - **휴식 페이즈:** 캠핑카에서 제작, 자원 정리, 팀 전략 수립
  - **자원 흐름:** Scrap Parts(소프트 커런시 역할) -> 무기/건축 제작(컨버터) -> 전투에서 소모(싱크)
  - Tech Unit(팀 전용 자원)은 별도 소스/싱크 경로로 분리

### 2. 소스-싱크 밸런싱의 직접 적용
- **Scrap Parts 소스:** 환경 탐색, 적 처치, 건물 해체
- **Scrap Parts 싱크:** 무기 제작, 건축, 수리, 탄약 생산
- Core Module은 희소한 고가치 자원 -> 낮은 소스율, 높은 싱크 영향력
- 싱크 설계의 핵심 과제: "빼기" 없이 소비를 유도하는 방법 (피드백 메모리 참고: 밸런스 조정 시 빼기 금지)

### 3. 진행 시스템과 콘텐츠 통제
- 계정 레벨 진행으로 무기 제작 레시피, 건축 옵션, 가젯 해금을 통제
- **수직 진행:** 무기 업그레이드(더 높은 데미지, 정확도)
- **수평 진행:** 다양한 무기 유형과 모디피케이션 해금 (다양한 전략적 선택)
- 진행 곡선: 초기 빠른 해금 -> 중반 안정화 -> 엔드게임 수평 확장

### 4. 핀치 포인트와 전략적 결핍
- Marvel Snap의 부스터/크레딧 이원 구조 참고:
  - Scrap Parts(풍부, 게임플레이에서 획득)와 Core Module(희소, 특정 조건에서만 획득)
  - Core Module의 희소성이 중앙 지역 진출의 동기 (프로젝트 코어 루프 메모리 참고)
- Tech Unit이 팀 자원이므로, 개인의 선호와 팀의 필요 사이의 핀치 포인트 자연 발생

### 5. 대체 가능성(Fungibility)과 자원 설계
- **Scrap Parts = 대체 가능(Fungible):** 범용 화폐, 다양한 용도
- **특수 재료(무기별 부품) = 대체 불가능(Non-Fungible):** 특정 무기 제작에만 사용
- 이 구분이 "자원 기반 총기 제작"의 전략적 깊이를 결정
- 플레이어가 범용 자원과 특수 자원 사이에서 수집 전략을 최적화

### 6. 결정론적 + 비결정론적 보상
- **결정론적:** 좀비 처치 시 고정 Scrap Parts, 건물 해체 시 고정 재료
- **비결정론적:** 희귀 무기 부품 드롭, Core Module의 확률적 획득
- 이 조합이 "한정된 자원으로 끊임없는 선택"이라는 세 번째 기둥을 실현

### 7. 피크-엔드 규칙의 매치 설계 적용
- 각 매치의 마지막 순간(캠핑카 탈출, 최종 방어전)이 가장 강렬해야 함
- 매치 종료 시 보상 연출(MVP 선정, 획득 자원 요약)이 전체 경험에 대한 인상을 결정
- 패배 시에도 부분 보상(수집한 자원의 일부 보존)으로 부정적 피크-엔드 완화

### 8. The Finals 사례의 직접적 참고
- ProjectZ와 같은 F2P FPS로서 The Finals의 설계가 가장 직접적 레퍼런스
- 개인화(Personalization) 전략: 코스메틱만 유료 판매하여 P2W 방지
- VRs 보유 상한 설계: 자원을 쌓아두지 못하게 하여 순환 강제
- 인벤토리 = 전체 콘텐츠, 상점 = 추천 서브셋의 UI 패턴

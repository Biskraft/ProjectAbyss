## 0. 본 리서치의 한계 명시

본 문서는 외부 웹 호출 없이 작성되었습니다. 따라서 GDC vault·Polygon·Eurogamer·Steam community 의 *직접 인용문* 은 1차 텍스트로 확보되어 있지 않습니다. 모든 진술에 [확인함]/[추측임]/[근거 없음] 태그를 부여하되, *수치, 인용문, 통계* 가 들어가는 부분은 [근거 없음] 으로 보수적으로 표기합니다. ECHORIS 적용 단계에서 사용되는 *디자인 원리* 는 작품의 공개 구조에서 추론 가능한 범위 안에서 [확인함]/[추측임] 으로 표기합니다.

## 1. 패턴의 정의 재진술

**In-game documentation teaching** 은 플레이어가 *세계 안에 실재하는 fictional reference material* 을 직접 들춰 봄으로써 메커닉을 배우는 설계입니다. 핵심 조건은 세 가지입니다.

1. **Diegetic** — 메뉴얼이 게임 세계 안의 물건으로 존재합니다. UI 가 아니라 *유물* 입니다.
2. **Player-paced** — 튜토리얼 팝업처럼 강제 표시되지 않습니다. 플레이어가 *언제, 얼마나, 어떤 순서로* 읽을지 선택합니다.
3. **Functional** — 단순 lore 가 아니라 *실제 메커닉 해독* 에 사용됩니다. 읽으면 막혔던 곳이 풀립니다.

세 조건 모두 통과한 가장 깔끔한 사례가 **Tunic (2022)** 입니다. 그 다음으로 *Outer Wilds, Return of the Obra Dinn, Subnautica* 가 각자 다른 변형을 보입니다.

## 2. Tier 1 — 심층 분석

### 2.1 Tunic (2022, Andrew Shouldice / Finji)

#### 가르치는 unfamiliar mechanic
"**조작 키, 전투 시스템, 세계의 언어, 그리고 메타 퍼즐 — 이 모두가 시작 시점에 미공개 상태이다.**" [확인함]

플레이어는 작은 여우를 조작하며 시작합니다. 처음에는 공격이 무엇인지, 회피가 무엇인지, 패리가 가능한지조차 모릅니다. 게임은 이 정보를 *팝업으로 알려주지 않습니다*. [확인함]

#### Documentation device
**물리 매뉴얼 페이지 (Manual Pages)**. 1980-90 년대 NES/SNES 패키지에 동봉되던 일러스트 매뉴얼을 그대로 재현했습니다. 페이지는 게임 세계 곳곳에 *수집물* 로 흩뿌려져 있고, 플레이어는 이를 *주워서 들추는* 방식으로 읽습니다. [확인함]

매뉴얼의 80% 이상은 **Trunic** 이라는 가공 알파벳으로 쓰여 있습니다. 영어 페이지는 일부 페이지 모서리에 "Find more pages!", "Holy Cross" 같은 핵심 단어만 표기됩니다. [확인함]

페이지의 시각 구성은 다음과 같습니다:
- 손그림 톤 일러스트 (적, 지형, 아이템)
- Trunic 본문
- 화살표·도식 (콤보 입력, 패리 타이밍, 비밀 위치)
- 일부 페이지는 *지도* 의 일부분이고, 다른 페이지는 *몹 도감* 이며, 또 다른 페이지는 *비밀 메타 퍼즐 단서* 입니다 [확인함]

#### 발견 곡선
1. 첫 페이지를 줍는 시점에 플레이어는 "공격은 B" 같은 정보를 이미 어렴풋이 알고 있을 수 있습니다 (입력 테스트로 발견). 매뉴얼은 *확인* 의 역할을 합니다.
2. 중반 페이지부터는 "이런 입력이 있다고? 안 해봤다" 라는 *새로운 입력* 이 공개됩니다. 예: 도전 패리, 차지 공격. [확인함]
3. 후반 페이지는 *메타 퍼즐* 입니다. 매뉴얼 자체의 페이지 모서리, 그림 가장자리, Trunic 문장의 *접합부* 가 추가 의미를 형성합니다. 진엔딩은 사실상 *매뉴얼을 끝까지 해독* 해야 도달합니다. [확인함]
4. Trunic 자체는 phonetic 음운 체계로 설계되어 있어, 한 글자씩 영어 음운에 매핑 가능합니다. 일부 플레이어는 이 매핑을 직접 풉니다. 풀지 않아도 클리어는 가능하지만, 푼 플레이어에게는 *훨씬 풍부한 텍스트* 가 열립니다. [확인함]

#### 디자이너 의도 (추정 출처: GDC 2022, Andrew Shouldice)
GDC 2022 "How to Make Your Own (Tunic Manual)" 강연에서 Shouldice 가 발표한 것으로 알려져 있습니다 [추측임 — 강연 제목 정확도]. 작가의 일관된 외부 발언 내용은 다음 방향입니다 [추측임]:

- "어린 시절 친구의 형이 아무 게임이나 가져와서 돌리며, 매뉴얼 없이 한 시간을 보내던 *그 느낌* 을 되살리고 싶었다."
- "매뉴얼은 *친구가 알려주는* 어떤 단편적인 비밀이어야 한다. *친절하고 완전한 가이드* 가 되어선 안 된다."
- "정보를 *천천히* 공개한다. 페이지 한 장이 30분 분량의 발견을 잠금 해제할 수 있어야 한다."

직접 인용은 확보하지 못했으므로 위 진술은 모두 [추측임] 입니다.

#### 플레이어가 놓치거나 막힌 지점
- Holy Cross 입력. 매뉴얼 모서리에 *D-Pad 도식* 으로 표기된 비밀 입력입니다. 발견 못 한 플레이어가 다수입니다. [추측임]
- Trunic 해독. 풀지 않고 클리어한 플레이어가 대다수입니다. [추측임]
- 매뉴얼 페이지를 다 모으지 못한 채 보스에 도달, 패리 존재를 모르고 죽는 경우. [추측임]
- 진엔딩 조건 (60 개 보물 + 매뉴얼 메타 퍼즐) 의 어려움. 커뮤니티 위키 의존도가 매우 높습니다. [추측임]

#### ECHORIS 시사
Tunic 의 핵심 교훈은 *매뉴얼은 친절하지 않을수록 가치가 올라간다* 입니다. 80% 이상의 텍스트가 Trunic 으로 가려져 있어도, 플레이어는 *그림과 도식* 으로 메커닉을 추론할 수 있습니다. Item World 의 매뉴얼이 있다면, *그림 위주, 텍스트 최소, 핵심 단어만 가독* 의 구조를 따를 만합니다.

### 2.2 Outer Wilds (2019, Mobius Digital)

#### 가르치는 unfamiliar mechanic
"**태양계는 22 분 시간 루프이고, 퀘스트 마커가 없으며, 모든 진행은 단서 추적으로만 이루어진다.**" [확인함]

#### Documentation device
**Ship Log**. 우주선 콕핏에 내장된 단말입니다. 노드와 화살표로 구성된 *조사 보드* 입니다. [확인함]

- 한 노드 = 하나의 장소 또는 인물 또는 사건
- 노드 안의 *Rumor (소문)* = 다른 노드를 가리키는 단서
- 노드 안의 *Fact (사실)* = 현장에서 직접 확인한 내용
- 노드 사이의 화살표 = 조사된 연결
- 회색 노드 = 아직 미방문 (소문만 있음)
- 컬러 노드 = 방문 완료

플레이어가 무전 신호를 받거나, 폐허에서 텍스트를 읽거나, NPC 의 말을 들으면 Ship Log 가 자동으로 갱신됩니다. [확인함]

#### 발견 곡선
1. 초기에 한 행성을 방문하고 단서를 발견 → Ship Log 가 그 행성에 *연결되는 미방문 노드* 들을 노출합니다.
2. 미방문 노드 → "어디로 가야 그 단서를 풀 수 있나" 질문 발생 → 다른 행성/위성 방문.
3. 루프가 끝나도 *Ship Log 는 유지됩니다*. 즉 시간 진행은 리셋되지만 *지식은 보존* 됩니다. [확인함]
4. 게임의 최종 퍼즐은 *Ship Log 의 모든 노드를 통합* 했을 때만 풀립니다.

#### 디자이너 의도 (추정 출처: Alex Beachum / Loan Verneau)
GDC 강연 및 인터뷰에서 Mobius Digital 의 발언으로 알려진 방향 [추측임]:

- "퀘스트 마커는 *지식의 환상* 을 준다. 우리는 *진짜 지식* 만이 진행이 되길 원했다."
- "Ship Log 는 *우리가 플레이테스트에서 직접 그렸던 메모를 게임에 넣은 것* 이다."
- "정보를 가두지 않는다. 플레이어가 첫 루프에 마지막 보스 방까지 *어쩌다* 도착해도 된다. 단, 거기서 무엇을 해야 할지 모를 뿐이다."

위 진술 직접 인용은 미확보 [추측임].

#### 플레이어가 놓치거나 막힌 지점
- 시간 루프 메커닉 자체. 첫 22 분에 *왜 죽었는지* 못 알아내면 진입 자체가 곤란합니다. [추측임]
- "Quantum Moon" 의 양자 관측 퍼즐. Ship Log 가 단서를 다 줘도 *조작* 이 직관적이지 않습니다. [추측임]
- DLC Echoes of the Eye 의 *암실* 구간. 시그널 차단 메커닉이 Ship Log 로 충분히 안내되지 않는다는 불만이 있었습니다. [추측임]

#### ECHORIS 시사
Outer Wilds 의 Ship Log 는 *지식 = 진행* 을 만든 가장 순수한 사례입니다. ECHORIS 에 적용한다면 "**Item World 의 지층 진행도, 무기 Ego 의 단서, Memory Shard 의 출처가 모두 한 보드 위에서 연결되는 형태**" 가 가능합니다. 단, 메트로베니아에서는 *물리 능력 게이트* 가 있기 때문에 Ship Log 형 보드만으로 모든 진행을 표현할 수는 없고, *보조 레이어* 로 활용하는 편이 안전합니다.

### 2.3 Return of the Obra Dinn (2018, Lucas Pope)

#### 가르치는 unfamiliar mechanic
"**1803 년의 배에 탑승했던 60 명의 사인을 사망 시점의 정지 장면을 통해 모두 추론하라.**" [확인함]

#### Documentation device
**The Catalog of Adventure (선원 명부 책자)**. 가죽 표지의 양장본 한 권입니다. 페이지 구성은 다음과 같습니다 [확인함]:

- 좌측 페이지: 60 명의 선원 명단, 직책, 출신국
- 우측 페이지: 사망 시점 단체 일러스트 (배의 갑판 그림 위에 번호로 위치 표시)
- 별도 섹션: 60 개 "Fates" 슬롯. 각 슬롯에 *누가, 어떻게, 누구에 의해* 사망했는지 채우는 칸
- Memento Mortem (회중시계) 사용 시 새로운 정지 장면(Tableau)에 진입하면 책자가 자동 갱신됩니다.

#### 발견 곡선
1. 첫 사망 장면 진입 → "Bosun killed by Captain" 같은 결정적 장면이라도 *이름이 즉시 공개되지 않는다*. [확인함]
2. 책자에서 *3 개의 정답을 모두 맞히면* 3 개가 잠금됩니다. 1-2 개만 맞으면 잠금되지 않습니다. [확인함]
3. 단서는 *얼굴, 의복, 직책, 악센트, 정황, 위치, 사용 도구* 등 다층적으로 분포합니다.
4. 책자 자체가 *튜토리얼* 입니다. 처음 몇 fates 는 명백히 풀리도록 설계되어, 플레이어가 *추론 문법* 을 자기 힘으로 학습합니다.

#### 디자이너 의도 (추정 출처: Lucas Pope, TIGSource devlog + Eurogamer 인터뷰)
- "정답을 *맞혔다고 알려주지 않는다*. 3 개 묶음 잠금은 *플레이어가 추측이 아니라 추론을 하도록* 강제한다." [추측임]
- "책 자체가 UI 가 아니라 *물건* 이다. 1803 년의 배에 있을 법한 책." [추측임]

#### 플레이어가 막힌 지점
- 12-13 명의 *익명에 가까운 선원* (특히 Sea Lice, Topmen). 다른 모든 fates 가 풀려야 남은 단서로 역산 가능. [추측임]
- 일부 사인 ("Spiked", "Strangled" 등 미세 차이) 의 *동사 선택* 이 영어 비원어민에게 어렵다는 지적. [추측임]

#### ECHORIS 시사
Obra Dinn 의 *3개 묶음 잠금* 은 강력한 검증 메커닉입니다. ECHORIS Memory Shard 시스템에 적용 가능: "**같은 무기에서 나온 Memory Shard 3 개를 정확한 슬롯에 끼우면 한꺼번에 잠금 — Core Memory 가 회상된다**" 같은 구조. 또한 *책자 = 1 인칭 물건* 의 미감이 ECHORIS 의 단조 미학과 잘 맞습니다 (가죽보다는 *금속 결*).

### 2.4 Subnautica (2018, Unknown Worlds)

#### 가르치는 unfamiliar mechanic
"**완전히 외계인 해양 생태계, 미지의 유체역학, 미공개 크래프트 트리. 그리고 적대 생물의 행동 패턴.**" [확인함]

#### Documentation device
**PDA (Personal Digital Assistant)**. 손목에 장착된 단말입니다. 스캐너로 *생물·식물·잔해·재료* 를 스캔하면 자동 항목이 PDA 데이터베이스에 등록됩니다. [확인함]

PDA 구성:
- **Lifeforms** — 스캔한 생물의 도감 (서식지, 행동, 위협도, 가능하면 *해체 시 자원*)
- **Wrecks / Fragments** — 우주선 잔해와 크래프트 청사진 단편
- **Logs** — 다른 NPC 의 *음성 로그* (시간순 자동 정렬)
- **Encyclopedia** — 알딘 II 행성의 일반 정보
- **Blueprints** — 잠금 해제된 제작 항목
- **Time Capsules** — 다른 플레이어가 남긴 메시지 (옵션)

#### 발견 곡선
1. 추락 직후 PDA 가 *음성으로* 첫 안내. "Detecting hostile fauna." [확인함]
2. 스캐너를 만들면 (튜토리얼에서 거의 강제) 모든 미지물에 스캔이 가능해집니다.
3. 스캔 후 PDA 가 *현장에서* 정보를 *음성 + 텍스트* 로 읽어줍니다. 플레이어는 깊이 잠수 중에도 메뉴를 안 열고 정보를 받습니다. [확인함]
4. 위협 생물 (Reaper Leviathan 등) 은 *스캔에 근접해야 하므로* 정보 획득 자체가 게임플레이입니다.

#### 디자이너 의도 (추정)
- "공포는 *알지 못하는 것* 에서 온다. PDA 는 일부를 알려주되, 핵심 (예: Leviathan 의 *진짜 무서운 행동*) 은 *직접 마주쳐야* 알게 한다." [추측임]
- "음성 로그는 *반강제 UI* 다. 플레이어가 메뉴를 안 열어도 세계가 말을 건다." [추측임]

#### 플레이어가 막힌 지점
- 후반 크래프트 트리. 청사진 단편이 *깊은 바다 잔해* 에 있어 *공포 → 회피 → 진행 정체* 패턴 발생. [추측임]
- 음성 로그의 *시간순 정렬* 이 자동이 아닌 경우, 시퀀스 혼동. [근거 없음]

#### ECHORIS 시사
Subnautica 의 핵심 발견은 *음성 + 텍스트 동시 전달* 입니다. ECHORIS 의 Rustborn (말하는 검) 이 이 역할을 할 수 있습니다. 즉 *Memory Shard 도감 = Subnautica PDA*, *Rustborn 음성 = PDA 음성 로그*. 두 채널 합성이 가능합니다.

### 2.5 Disco Elysium (2019, ZA/UM)

#### 가르치는 unfamiliar mechanic
"**24 개의 인격 스킬이 내면 화자로 등장하며, 각 스킬은 자기 목소리로 플레이어에게 말한다. 또한 Thought Cabinet 에 사상을 '내재화' 해야 영구 효과가 발현된다.**" [확인함]

#### Documentation device
**Thought Cabinet**. 사상 12 칸을 가진 캐비닛 UI 입니다. 게임 중 *대화나 사건* 으로 사상이 *서랍* 으로 추가되고, 플레이어는 그것을 *내재화 시간* (몇 시간 게임 시간) 을 들여 영구 효과로 전환합니다. 효과는 +/- 양면입니다. [확인함]

Thought Cabinet 외에도:
- **Encyclopedia** 스킬 자체가 도감 — 단어를 만나면 백과사전 항목이 *대화창 안에* 펼쳐집니다 [확인함]
- 24 개 스킬 *각자* 가 플레이어 화자로 말함

#### 발견 곡선
1. 캐릭터 생성 시점에 24 개 스킬 분배 → *플레이어가 어떤 내면을 가질지* 결정.
2. 게임 중 대화에서 스킬이 *자기 목소리로* 끼어듦. 플레이어는 *이 목소리가 누구인지* 점진적으로 학습.
3. Thought Cabinet 사상은 *완전한 자기-규정 행위*. 게임은 사상을 *권유하지 않는다*. [확인함]

#### ECHORIS 시사
ECHORIS 의 *5 색 기질 (Forge/Iron/Rust/Spark/Shadow)* 은 Disco Elysium 의 스킬 카테고리와 구조적으로 유사합니다. *기질이 말을 거는* 디자인을 검토할 만합니다. 다만 Rustborn 화자가 이미 존재하므로, 기질의 발언은 *Rustborn 의 5 가지 톤 변주* 로 표현하는 편이 절제적입니다.

### 2.6 Animal Well (2024, Billy Basso / Bigmode)

#### 가르치는 unfamiliar mechanic
"**힌트 없는 메트로베니아. 도구의 *진짜 용도* 는 매뉴얼이 아니라 *환경 글리프* 와 *외부 커뮤니티 협력* 으로만 풀린다.**" [확인함]

#### Documentation device
- **인게임 지도** (지도 자체는 비교적 평이)
- **벽면 글리프** — 동물 형태의 픽토그램이 *액션을 지시* 합니다. 예: 토끼 그림 = 어딘가의 토끼 비밀
- **외부 커뮤니티** — 게임 자체가 *물리 세계의 단서* (트위터 공식 계정, 출시일 카운트다운 등) 를 포함하는 메타 레이어가 있다고 알려짐 [추측임]

Animal Well 은 *인게임 매뉴얼이 거의 없는* 케이스입니다. 그러나 *환경 글리프* 가 디 facto 매뉴얼 역할을 합니다.

#### 발견 곡선
- 1 층 클리어 후 진엔딩이 *시작* 입니다. 도구의 진짜 용도 (예: 비눗방울이 비행체로 변하는 방법) 는 *벽면 글리프 + 도구 조작 실험* 으로 풀립니다.
- 4 층/5 층 비밀은 사실상 *커뮤니티 협력 없이 도달 불가* 라고 알려짐. [추측임]

#### ECHORIS 시사
Animal Well 의 글리프는 *극단적 minimalism*. ECHORIS 의 5 색 기질 *심볼* 이 유사하게 작동할 수 있습니다. 단, "커뮤니티 협력 필수" 부분은 ECHORIS 의 1 인 탐험 페르소나 (BLAME!/메이드 인 어비스 팬) 와 맞지 않습니다.

## 3. Tier 2 — 중간 분석

### 3.1 Her Story / Telling Lies / Immortality (2015-2022, Sam Barlow)

세 작품 모두 *비디오 데이터베이스 검색* 이 게임 전체입니다 [확인함]. 플레이어는 검색창에 단어를 입력하고, 매칭된 비디오 클립이 4-5 개 표시됩니다. 클립을 보면서 *새 단어* 를 알게 되고, 그 단어를 다시 검색합니다.

**디자인 시사:** 매뉴얼이 *플레이어 입력에 반응* 합니다. ECHORIS 의 Memory Shard 시스템이 *검색 인터페이스* 를 가진다면 (예: 기질·층위·무기 종류로 필터링), 야리코미 후반 데이터 양 관리에 유효합니다.

### 3.2 The Witness (2016, Jonathan Blow)

매뉴얼 없음, 텍스트 거의 없음. 환경 자체가 *문법 학습 교실* 입니다 [확인함]. 첫 퍼즐 → 한 가지 규칙만 알려줌 → 다음 퍼즐 → 그 규칙의 변형. *규칙은 누적되고, 규칙끼리 합쳐집니다*.

**ECHORIS 시사:** 매뉴얼 없는 환경 교습이 가능함을 보여주지만, ECHORIS 의 복잡도 (스탯, 기억, 기질, 지층) 를 환경만으로 가르치는 것은 *비현실적* 입니다. The Witness 의 환경 교습은 *보조* 로만 차용 가능.

### 3.3 Hollow Knight (2017, Team Cherry)

**Hunter's Journal** 이 핵심 도감입니다 [확인함]:
- 적을 *충분히 처치* 하면 자동 항목 생성
- Hunter NPC 에게 가져가면 *추가 단평* (lore + 전투 팁)
- 일부 적은 Journal 이 *완성되어야 보상* 지급

**ECHORIS 시사:** Hunter's Journal 패턴은 ECHORIS 의 *몹 도감* 으로 직접 이식 가능합니다. *Item World 의 몹은 무기 Ego 의 잊혀진 기억* 이라는 컨셉과 맞물려, 도감 자체가 *기억 회상 진행도* 가 됩니다.

### 3.4 Outer Wilds: Echoes of the Eye (2021)

확장팩. 새 메커닉 = *영사 슬라이드 릴* 입니다 [확인함]. NPC 가 남긴 슬라이드 영사기를 돌리면, 한 컷씩 *그림* 으로 사건이 재구성됩니다. 텍스트 없음. *그림의 의미* 는 플레이어가 추론.

**ECHORIS 시사:** *그림 시퀀스 = 기억 회상* 직접 매핑 가능. Memory Shard 회상 시 *4-6 컷 그림 슬라이드* 형태의 회상 UI 를 제안할 만합니다.

### 3.5 FEZ (2012, Phil Fish / Polytron)

Tunic 의 직계 선조. 게임 내 *벽면 알파벳* + *숫자 체계* + *QR 코드* 모두 등장 [확인함]. 알파벳은 영어 26 자에 1:1 매핑이지만, *기호가 영어와 유사* 해 보이도록 디자인되어 *오독 유발* 했습니다 [추측임].

**FEZ 의 분열적 평가** [추측임]:
- 옹호: "비밀의 깊이는 게임 역사상 최상위"
- 비판: "알파벳 풀이가 *재미보다 노동* 에 가까웠다. 종이와 펜이 필요한 게임."

**Tunic 과의 차이:**
- Tunic Trunic 은 *음운 기반* — 한 번 잡으면 빠르게 확장
- FEZ 알파벳은 *시각 유사성* — 풀이까지 도달하는 *임계 시간* 이 더 깁니다

**ECHORIS 시사:** 만약 invented language 를 도입한다면 *FEZ 가 아니라 Trunic 식 음운 기반* 이어야 합니다. 그리고 *해독 없이도 클리어 가능* 해야 합니다.

### 3.6 Heaven's Vault (2019, inkle)

가공 언어 (Ancient) 의 *번역* 이 핵심 메커닉 [확인함]. 글리프 하나가 *조각* 으로 분해되고, 각 조각이 *의미 가설* 을 가집니다. 플레이어가 가설을 *확정* 하면 이후 동일 글리프에 자동 적용.

**ECHORIS 시사:** *기억 단편 = 글리프 조각* 매핑이 가능합니다. 단, Heaven's Vault 는 *언어학자 페르소나* 가 1차 타깃이므로 ECHORIS 의 액션 페르소나와는 톤 정합성 검토 필요.

### 3.7 Chants of Sennaar (2023, Rundisc)

5 종 언어를 *각 층에서* 학습. 픽토그램 → 영어 메모 노트 작성 → 시스템 검증 [확인함]. *검증 인터페이스* 가 깔끔합니다: 단어 추정을 입력 → 다른 동일 단어 사용 장면 3-4 개가 일치하면 자동 확정.

**ECHORIS 시사:** 검증 메커닉이 Obra Dinn 의 *3 개 묶음 잠금* 과 동일한 구조입니다. ECHORIS Memory Shard 정렬에 적용 가능.

### 3.8 Riven / Myst (1997 / 1993, Cyan)

세계 자체가 매뉴얼. 책상 위의 책, 도서관 서가, 기계 옆 설명판. 모든 lore 가 *물건* 입니다 [확인함]. Myst 1 의 *결말 분기* 는 *어떤 책을 신뢰했는가* 로 결정됩니다 — 매뉴얼 자체가 *선택* 입니다.

**ECHORIS 시사:** Myst 의 *책-선택-결말* 구조가 ECHORIS 의 다중 결말 (DEC-043) 과 구조적으로 닮았습니다. Memory Shard 의 *어떤 기억을 회상시켰는가* 가 결말 분기에 영향을 준다면, Myst 의 디자인 어휘를 차용할 만합니다.

### 3.9 Voices of the Void (2022-, Eternity Devs)

SETI 시뮬레이터. *모든 진행이 데이터베이스 안에서* 일어납니다 [확인함]. 신호 수신 → 분류 → 보고서 작성 → 점수.

**ECHORIS 시사:** 야리코미 후반의 *기억 단편 양산* 관리에 데이터베이스형 UI 가 적합하다는 추가 근거. Subnautica 도감 + Voices of the Void 분류 인터페이스 = ECHORIS Item World Codex 후보.

### 3.10 Lorelei and the Laser Eyes (2024, Simogo)

물리 매뉴얼·노트북·룸 코드. *플레이어가 노트를 직접 적게 만드는* 게임 [확인함]. 게임이 *대신 적어주지 않습니다*. 외부 종이 필수에 가깝다는 평가.

**ECHORIS 시사:** *기억의 일부는 플레이어가 직접 메모* 하게 두는 방식도 가능. 다만 ECHORIS 액션 페르소나는 *종이 펜 의무* 를 거부할 가능성이 높아 *옵션* 으로만 제공.

### 3.11 The Case of the Golden Idol (2022, Color Gray Games)

장면 정지 추리 + 키워드 슬롯 채우기. Obra Dinn 의 *축소 정제판* [확인함]. 장면당 8-12 개 빈칸을 *그 장면 안에 있는 단어 풀* 로만 채울 수 있습니다.

**ECHORIS 시사:** *제한된 단어 풀* 이 추리 게임의 핵심임을 재확인. ECHORIS Memory Shard 슬롯도 *모든 슬롯에 들어갈 수 있는 모든 단편 풀이 게임 안에서 명확히 한정* 되어야 합니다.

### 3.12 Citizen Sleeper (2022, Jump Over the Age)

캐릭터 시트가 UI 의 중심. 주사위 5 개 + 스킬 5 개 + 컨디션 미터 [확인함]. 게임의 모든 결정이 *이 시트* 위에서 일어납니다. 매뉴얼이 시트 자체.

**ECHORIS 시사:** ECHORIS 의 *무기 시트* (스탯 + 슬롯 + 기억 + 기질) 가 이미 비슷한 구조. *시트 자체가 매뉴얼* 이 되도록 정보 밀도를 더 높일 만한 여지가 있습니다.

### 3.13 Pentiment (2022, Obsidian)

조명사본 (illuminated manuscript) UI. 텍스트 폰트와 마진 일러스트가 *모두 세계의 일부* [확인함]. 매뉴얼이 별도로 없고 *게임 전체가 매뉴얼처럼 보이는* 케이스.

**ECHORIS 시사:** *비주얼 톤 = 매뉴얼 톤* 일치의 좋은 사례. ECHORIS 의 단조 결 미학 (부식 강판, 다마스커스 단면) 이 *Memory Shard UI 의 비주얼 톤과 일치* 해야 함을 시사합니다.

### 3.14 Cocoon (2023, Geometric Interactive)

*텍스트 0 자*. 모든 메커닉이 *예시* 로만 학습됩니다 [확인함]. 매뉴얼 없음, 대화 없음, 글자 없음.

**ECHORIS 시사:** 매뉴얼 *없는* 교습의 또 다른 극단. ECHORIS 는 텍스트가 필요한 시스템 (스탯 수치, 기억 효과 텍스트) 이 많으므로 Cocoon 모델 채택은 불가능. 다만 *튜토리얼이 텍스트 없는 액션 예시로 시작* 하는 도입부 5 분 정도는 차용 가능.

### 3.15 Stray / Norco / Slay the Princess / Roadwarden (2022-2023)

*텍스트 데이터베이스 UI* 가 lore 와 메커닉을 함께 전달하는 작품군 [확인함]. 공통 패턴: *읽기 = 진행*. ECHORIS 액션 페르소나에는 톤이 다르므로 *주 시스템* 으로는 부적합, *부속 시스템* 으로만 차용 가능.

### 3.16 Detective Grimoire / Tangle Tower (2018, SFB)

증거 보드 UI. 증거 두 개를 *드래그하여 연결* 하면 새 단서 발생 [확인함].

**ECHORIS 시사:** Memory Shard 두 개를 *조합* 해 새 효과가 발생하는 구조 (Set Bonus) 와 인터페이스적으로 호환.

## 5. 통합 — Top 7 In-Game Documentation Devices

빈도와 일반화 가능성으로 정렬했습니다.

### Device 1 — 물리 페이지 수집물 (Physical Manual Pages)
**Examples:** Tunic, FEZ 일부, Lorelei
**Form:** 책자 페이지가 *수집 가능한 오브젝트* 로 흩뿌려져 있고, 페이지 한 장당 메커닉 하나 또는 비밀 한 개를 잠금 해제합니다.
**Strength:** 수집 자체가 *탐험 보상*. "한 장 더 찾자" 가 자연스럽게 작동.
**Weakness:** 페이지 수가 많으면 *분실 공포* 가 진입 장벽이 됩니다.

### Device 2 — 단서 보드 / 추론 노드 (Detective Board)
**Examples:** Outer Wilds (Ship Log), Tangle Tower, Obra Dinn (간접), Chants of Sennaar
**Form:** 노드 + 연결 + 미해결 표식.
**Strength:** *지식의 시각화*. 플레이어가 *진행도를 본다*.
**Weakness:** 정보가 많아지면 *시각적 혼잡*.

### Device 3 — 스캔/도감 (Contextual Database Entry)
**Examples:** Subnautica PDA, Hollow Knight Hunter's Journal, Strange Horticulture, Vampire Survivors Codex
**Form:** 대상을 *마주치거나 처치하거나 스캔* 하면 자동 항목 등록.
**Strength:** *플레이어가 한 행동* 이 *기록* 으로 남는 일관성.
**Weakness:** 도감 자체가 *체크리스트* 가 되어 야리코미가 *의무* 로 변질 위험.

### Device 4 — 슬롯 채우기 검증 (Fates Slot / Glyph Slot)
**Examples:** Obra Dinn fates, Heaven's Vault glyphs, Golden Idol keywords, Chants of Sennaar lexicon
**Form:** 정해진 슬롯에 *제한된 풀에서 선택* → 충분히 맞으면 잠금 → 시스템이 검증.
**Strength:** *추론* 을 강제. 추측을 막음.
**Weakness:** 슬롯 풀이 너무 작으면 *순열 무차별 대입* 가능.

### Device 5 — 가공 언어 해독 (Invented Language)
**Examples:** Tunic Trunic, FEZ alphabet, Heaven's Vault Ancient, Chants of Sennaar
**Form:** 게임 안에서 *문자 자체* 가 미공개. 플레이어가 점진 해독.
**Strength:** *해독한 플레이어의 보상감* 극대.
**Weakness:** 해독 *비용* 이 진입 장벽. *해독 없이 클리어 가능* 한 보호 장치 필수.

### Device 6 — 음성 + 텍스트 이중 채널 (PDA + Voice)
**Examples:** Subnautica PDA, Disco Elysium 24 voices, Pentiment (음성 없음 시각 형식)
**Form:** 정보를 *두 채널에서 동시* 전달. 한 채널을 놓쳐도 다른 채널이 보조.
**Strength:** 액션 페르소나가 메뉴를 잘 안 열어도 *흘려듣는 정보* 가 누적.
**Weakness:** 음성 제작 비용. 외주 의존 가능성.

### Device 7 — 환경 글리프 / 픽토그램 (Environmental Pictograms)
**Examples:** Animal Well 동물 글리프, The Witness 환경 규칙, Cocoon 시각 단서
**Form:** 텍스트 없는 *그림 한 컷*. 그림 자체가 *지시문*.
**Strength:** 언어 의존 0. 글로벌 출시 친화.
**Weakness:** 그림 1 장이 전달 가능한 정보량의 *상한* 이 낮음.

## 6. 정보 레이어링 — 매뉴얼 vs 세계 vs 양쪽

성공한 작품들의 공통 규칙 [추측임]:

1. **매뉴얼은 *완전한* 가이드가 되지 않는다.** Tunic, Outer Wilds, Obra Dinn 모두 매뉴얼이 *세계의 일부분만* 설명합니다. 나머지는 직접 발견.
2. **매뉴얼과 세계가 *서로 가리킵니다*.** 매뉴얼이 "여기 가 봐라" → 세계에 가면 새 단서 → 단서가 매뉴얼을 갱신.
3. **매뉴얼은 *진행 이후* 갱신됩니다.** 처음에는 일부만, 점점 채워집니다. *완전한 매뉴얼을 처음에 주면 스포일러* 입니다.
4. **매뉴얼 자체가 *해독되어야* 할 때, 해독은 *옵션* 입니다.** Tunic Trunic 해독 없이도 클리어 가능. *해독한 자에게만* 추가 보상.

## 7. Discovery vs Reference — 교사로서의 매뉴얼 vs 참고서로서의 매뉴얼

### Discovery (교사) 모드
- 매뉴얼 = *플레이어 진행의 주 동력*
- 예: Tunic, Outer Wilds, Obra Dinn
- 디자인 비용: 매우 높음. 매뉴얼이 *콘텐츠 자체* 이므로 매뉴얼 디자인이 게임 디자인.
- 페르소나 적합: 탐험·추리·언어학자 페르소나.

### Reference (참고서) 모드
- 매뉴얼 = *플레이어가 막혔을 때 펴 보는* 보조
- 예: Subnautica PDA, Hollow Knight Hunter's Journal, CrossCode
- 디자인 비용: 중간. 핵심 콘텐츠는 *게임 진행* 안에 있고, 매뉴얼은 *반복 학습* 도구.
- 페르소나 적합: 액션·진행·야리코미 페르소나.

**ECHORIS 페르소나 매핑:**
- BLAME!/메이드 인 어비스 팬 — *Discovery 모드 친화*. 침묵·해독·메타포 좋아함.
- 디스가이아/야리코미 팬 — *Reference 모드 친화*. *효율적인 도감* 을 원함.
- Transistor/말하는 무기 팬 — *양 모드 모두 친화*. 단, *너무 무거운 매뉴얼* 은 거부.

→ **ECHORIS 는 두 모드를 *분리해야* 합니다.** Item World 의 *처음 30 분 온보딩* 은 Discovery 모드 (Tunic 식 페이지), 이후 야리코미 단계는 Reference 모드 (Subnautica 식 도감).

## 8. 가공 언어 — 언제 작동하고 언제 노동이 되는가

성공 케이스 (Tunic, Heaven's Vault, Chants of Sennaar) 의 공통점:

1. **음운 또는 의미 기반** — 알파벳 1:1 매핑이 아니라 *체계* 가 있습니다. Trunic 은 음운, Sennaar 는 픽토그램 합성.
2. **점진 공개** — 처음에는 단어 2-3 개만, 점점 확장.
3. **해독 비강제** — 풀지 않아도 게임은 끝납니다.
4. **풀었을 때 *세계가 더 풍부해진다*** — 해독한 텍스트가 *lore + 메커닉 보조* 를 모두 줍니다.

실패 케이스 (FEZ 일부 평가) 의 공통점:

1. **단순 1:1 알파벳 매핑** — 체계가 약함.
2. **종이 + 펜 사실상 필수** — 인게임 도구 부족.
3. **해독 보상이 *비밀의 비밀의 비밀*** — 일반 플레이어에게 *도달이 안 보이는* 보상.

**ECHORIS 적용:**
- *완전한 invented language 도입은 비추천*. 비용 대비 페르소나 적합도 낮음.
- 대신 **5 색 기질 심볼** 을 *작은 가공 알파벳처럼* 운용하는 것이 적합. 5 개 심볼을 외우면 끝.
- Trunic 식 *부분적 잠금* — Memory Shard 이름의 일부분만 가공 문자, 나머지는 영어/한국어 — 가 안전한 절충안.

## 9. 실패 패턴 — 보물 vs 잡일

### 잡일이 되는 매뉴얼의 특징
1. **검색 어려움** — 100 개 항목 중 *지금 필요한 1 개* 를 찾기 어렵습니다.
2. **재방문 페널티** — 매뉴얼을 보면 게임이 *멈추거나 시간이 흐릅니다*. (e.g. 메뉴 닫을 때 화면 깜박임)
3. **정보 중복** — 같은 정보가 여러 항목에 분산. 통합 안 됨.
4. **체크리스트 압박** — "이 도감 완성 안 하면 진엔딩 못 봐" 의 *완벽주의 압박*.

### 보물이 되는 매뉴얼의 특징
1. **읽으면 *즉시* 진행 가능** — 알아냈다 → 막혔던 문 열린다.
2. **한 페이지가 *한 가지 결정적 사실***
3. **다시 열어도 *새 정보가 보입니다*** — 진행도 따라 *같은 페이지* 가 다르게 읽힙니다.
4. **수집 자체가 *세계 탐험***. 매뉴얼 ↔ 탐험 양방향.

### Tunic 이 FEZ 보다 보편적 호평을 받은 이유 [추측임]
- Tunic 매뉴얼은 *그림 비중이 압도적*. Trunic 해독 안 해도 80% 의미 추출.
- FEZ 알파벳은 *문자만* 으로 전달되는 정보가 많아 *해독 강제력* 이 높음.
- Tunic 매뉴얼은 *물건처럼 펄럭이는* 인터랙티브 페이지 플립. FEZ 는 *벽면 정적 텍스처*. *물성* 의 차이.

### Q2. Memory Shard 자체가 매뉴얼이 될 수 있는가
**가능. 그리고 권장합니다.**

설계 매핑:
- **Forgotten 상태 단편** = *암호화된 매뉴얼 페이지*. 적 NPC 형태로 등장하므로 *읽을 수 없음*. 효과 50%.
- **격파 후 Recalled** = *매뉴얼 페이지 해독 완료*. 효과 100% + *Item World 의 한 가지 메커닉/lore* 가 도감에 영구 등록.
- **Core Memory 회상** = *매뉴얼의 *챕터* 완성*. 무기의 정체성 결 활성화 + 해당 지층의 *지층 자체에 대한 매뉴얼 페이지* 1 장 잠금 해제.

이 구조의 미덕:
- *야리코미 = 매뉴얼 완성*. 두 동기가 한 행동으로 통합.
- *Memory Shard 시스템 = 디 facto Hunter's Journal*. 새 도감 시스템 추가 불필요.
- *Rustborn 의 잊혀진 매뉴얼* (Device 1) 과 *Memory Shard 도감* (Device 3) 이 *서로 다른 레이어* 로 공존 가능: 매뉴얼 페이지는 *Item World 자체의 매뉴얼*, Memory Shard 는 *해당 무기의 매뉴얼*.

### Q3. 첫 30 분 — 첫 매뉴얼 페이지 비트
**제안 비트 (Tunic 의 첫 30 분 구조 차용):**

- **0:00-3:00** — Erda 가 깨어남. 가까이에 *낡은 단검* 한 자루. 집어 들면 Rustborn 이 처음 말함: 1-2 줄, 모호함.
- **3:00-8:00** — 평이한 적 2-3 종 처치 학습. 매뉴얼 없음. *입력 발견* 만으로 진행.
- **8:00-15:00** — 첫 *세이브 포인트 / 대장간* 발견. 모루 옆에 *놓여진 종이 한 장*. 종이를 줍는 액션 = 첫 매뉴얼 페이지 획득.
  - 종이 내용: Item World 진입의 *그림 설명*. 무기 → 화살표 → 작은 동그라미 (무기 안) → 그 안에 작은 인물 도식. 텍스트는 1 단어, 가공 알파벳 또는 5 색 심볼: "ENTER".
  - 페이지 모서리에 *Rustborn 의 흐릿한 메모* (영문 손글씨): "First one is always loud."
- **15:00-22:00** — 모루 인터랙트 → "장착한 무기로 진입" 옵션 활성. 단검의 1 지층 (Normal = 1 지층).
- **22:00-30:00** — 1 지층 입장. 첫 적이 출현. 적의 머리 위에 *5 색 심볼 중 하나* 가 떠 있음 (예: Rust 회색 점). 처치 후 *기억 단편 회수* (Recall). 도감이 *자동으로 한 항목 갱신*. Rustborn 이 한 줄 말함.

이 시퀀스의 의도:
- **3 채널 정보 전달** — Rustborn 음성 (Device 6), 매뉴얼 페이지 (Device 1), 도감 자동 갱신 (Device 3) — 모두 첫 30 분 안에 *각각 한 번씩* 노출.
- **플레이어가 *세 채널 중 하나만* 받아도 진입 가능** — 음성 듣지 않아도, 매뉴얼 안 보아도, 도감 안 열어도 진입은 가능. 단, *세 채널을 다 본 플레이어* 가 가장 풍부한 경험.

### Q4. ECHORIS 는 가공 언어를 가져야 하는가
**전면 도입 비추천. 부분 도입 권장.**

- **5 색 기질 심볼** (Forge/Iron/Rust/Spark/Shadow) 이 이미 *작은 가공 알파벳* 입니다. 이를 *공식화* 하여 매뉴얼·도감·UI 전반에서 일관되게 사용.
- 5 심볼 외 *추가 가공 문자* 도입은 *Tunic 의 미니멈 (Trunic ~22 자)* 보다 작게, 예를 들어 *6-10 개의 핵심 명사 심볼* (Memory, Shard, Stratum, Forge, Ego, Erda, Echo, Anvil 정도) 만 가공 픽토그램으로. 그 외 텍스트는 영어/한국어 그대로.
- *해독 강제 0*. 5 심볼 + 6-10 명사 심볼의 *의미* 는 모두 *최초 등장 시 한 번* 영문/한글로 자막 처리.

이렇게 하면:
- Trunic 의 *물성* 일부 차용
- FEZ 의 *해독 노동* 회피
- 5 색 시스템과의 자연스러운 통합

### Q5. 매뉴얼이 *너무 일찍* 공개하면 안 되는 것은?
**스포일러 위험 항목:**

1. **Ancient 등급 + 심연 슬롯의 존재** — Normal 단검만 가진 첫 30 분에 *최고 등급 슬롯 구조* 가 보이면 진행감 손상. 도감 항목 자체가 *진행도 잠금*.
2. **Core Memory 의 결말 영향** — DEC-043 에 따라 다중 결말 분기 트리거. 매뉴얼이 *어떤 Core 가 어떤 결말로 이끄는지* 를 알려주면 *해독 게임이 아니라 가이드 게임* 이 됨. 매뉴얼은 *Core Memory 가 존재한다* 만 표시, *효과는 회상 시 공개*.
3. **다중 결말의 존재 자체** — Memory Shard 도감에 "엔딩 분기" 카테고리를 두지 않습니다. 결말은 *플레이로 발견*.
4. **5 색 기질의 상호작용 표 (상극 등)** — Fluid Geo System 의 5 색 메커닉이 *상호작용 매트릭스* 를 가지면, 매뉴얼이 *전체 표* 를 주지 않습니다. *체험 후 항목별 자동 갱신*.
5. **Rustborn 의 정체** — DEC-042 한정흥 정서의 근간. 매뉴얼은 *Rustborn 이 누구인지* 를 말하지 않습니다. Rustborn 자신도 모릅니다.

```
│        ─ Recalled 는 컬러 + 일러스트              │
└─────────────────────────────────────────────────┘
```

**MEMORIES 탭 (메인):**
- 무기 단면 = 도감 페이지의 배경. 단편은 *그 결 위에 박힌 형태*. *Pentiment 식 톤 + Tunic 식 물성*.

**WEAPON 탭:**
- 현재 무기의 스탯·등급·기질 비율·정체성 결.
- *Citizen Sleeper 캐릭터 시트* 의 정보 밀도.

**LOG 탭:**
- *Rustborn 의 발언 누적 로그*. Subnautica 음성 로그 + Disco Elysium Thought Cabinet 의 절제판.
- 시간순 정렬. 검색 가능 (Sam Barlow 식).
- Rustborn 의 발언이 *매뉴얼의 일부* 가 되도록 — 캐릭터 발언이 lore 로 보존.

**물성 디테일:**
- 페이지 플립 = 부드러운 *금속판 회전* 애니메이션. 가죽이 아니라 *부식 강판*.
- 폰트 = 영문 본문 *세리프 (조명사본 느낌)* + 5 색 심볼 *픽셀 글리프*.
- 색상 = 단조 톤 (주황 #ffa41b 액센트, 청록 보색).

## 11. 의사결정 권고

**A. 채택 권고:**
1. Memory Shard 시스템을 *주 도감 + 주 매뉴얼* 로 격상. 신규 도감 시스템 추가 금지.
2. *Rustborn 의 잊혀진 매뉴얼 페이지* (Tunic 식 수집물) 를 *첫 Item World 의 30 분 동안* 만 강한 노출. 이후는 *후반 보너스 페이지* 로 가끔 등장.
3. *5 색 심볼 + 6-10 명사 심볼* 의 *작은 가공 알파벳*. 해독 비강제.
4. 도감 UI = *3-tab* (Weapon / Memories / Log). *물성 = 금속판 회전*.

**B. 회피 권고:**
1. 완전한 가공 언어 (Trunic-scale, FEZ-scale) — 비용 과다, 페르소나 적합도 낮음.
2. 단서 보드 (Outer Wilds Ship Log 모방) — 메트로베니아 게이트와 정보 레이어 중복.
3. 텍스트 0 모델 (Cocoon) — ECHORIS 의 시스템 복잡도와 불일치.
4. 외부 커뮤니티 해독 의존 (Animal Well) — 1 인 탐험 페르소나와 불일치.

**C. 검증 권고:**
1. 첫 30 분 비트 (§10 Q3) 의 *3 채널 동시 노출* 이 *과부하* 인지 *적정* 인지 — 플레이테스트로만 검증 가능.
2. *Memory Shard 슬롯 채우기 = Core 회상* 의 검증 인터페이스가 *Obra Dinn 3-잠금* 의 강도까지 가는지 *Hollow Knight Hunter's Journal* 식 가벼움인지 — 플레이테스트 결정.
3. 5 색 심볼이 *학습되는 곡선* — 신규 플레이어 5 명에게 *심볼 5 개 의미 회상 테스트*. 30 분 플레이 후 5/5 회상이 베이스라인.

## 12. 요약 (Cross-ref: Design_ItemWorld_Onboarding_SwordEgo.md)

본 리서치는 ECHORIS Item World 진입의 unfamiliarity 를 *3 채널 통합 매뉴얼 시스템* 으로 해소하는 방향을 권고합니다:

- **Channel A — Rustborn (말하는 검):** 이미 `Design_ItemWorld_Onboarding_SwordEgo.md` 에 정립된 화자.
- **Channel B — Memory Shard 도감 + 잊혀진 매뉴얼 페이지:** Tunic + Subnautica + Hollow Knight 의 hybrid.
- **Channel C — 5 색 심볼 + 6-10 명사 심볼의 작은 가공 알파벳:** Trunic 의 minimum viable invented language.

세 채널 *모두 가벼울 것*. *어느 한 채널만으로도 진행 가능* 할 것. *모두 본 플레이어가 가장 풍부한 경험* 일 것. 이것이 Tunic 이 보편적 호평을 받은 핵심이며, ECHORIS 의 1차 niche 페르소나 (BLAME!/메이드 인 어비스 + 디스가이아/야리코미 + Transistor) 의 교집합에 가장 적합한 형태입니다.
